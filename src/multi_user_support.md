# Проблема: Ограничение одного пользователя

## Описание проблемы

Здесь опиши, что происходило не так. Например:
*   Приложение могло корректно работать только с одним пользователем одновременно.
*   Когда второй пользователь входил в систему (логинился через DonationAlerts), он "перехватывал" сессию.
*   Слушатель донатов (`CentrifugoListener`) переключался на второго пользователя, и донаты для первого переставали отслеживаться.
*   Сообщения о донатах (через WebSocket) отправлялись всем подключенным браузерам, а не только тому пользователю, которому пришел донат.

## Причина проблемы (Root Cause)

Объясни, *почему* так происходило:
*   Использовался **глобальный**, единственный экземпляр `TokenStorage`, который хранил токены только последнего залогинившегося пользователя в одном файле (`da_token.json`).
*   Использовался **глобальный**, единственный экземпляр `CentrifugoListener`, который мог слушать донаты только для одного пользователя (того, чьи токены были в `TokenStorage`).
*   `WebSocketManager` отправлял сообщения (`broadcast`) всем активным соединениям без разбора, какому пользователю они принадлежат.

## Реализованное решение

Опиши, как проблема была решена:
1.  **Хранение токенов по пользователям:**
    *   `TokenStorage` был изменен для хранения токенов в отдельных файлах для каждого `user_id` в директории `user_tokens/`.
    *   Теперь `TokenStorage` может загружать, сохранять и проверять токены для конкретного пользователя.
2.  **Менеджер слушателей (`ListenerManager`):**
    *   Создан новый класс `ListenerManager`.
    *   Он отвечает за создание и управление **отдельными** экземплярами `CentrifugoListener` для каждого `user_id`, у которого есть сохраненные токены.
    *   Каждый `CentrifugoListener` теперь инициализируется с `user_id` и слушает только его канал донатов.
3.  **Идентификация WebSocket-соединений:**
    *   При успешном OAuth-логине `user_id` теперь сохраняется в **сессии** пользователя (`request.session['user_id']`).
    *   Когда фронтенд подключается по WebSocket, бэкенд (`websocket_endpoint` в `main.py`) проверяет `user_id` в сессии этого WebSocket-соединения.
    *   `WebSocketManager` теперь хранит связь между `user_id` и его активными WebSocket-соединениями (`user_connections`).
4.  **Адресная рассылка сообщений:**
    *   `CentrifugoListener` при получении доната теперь передает `user_id` в `_process_and_broadcast`.
    *   `WebSocketManager` получил метод `broadcast_to_user(user_id, data)`, который отправляет данные только тем WebSocket-соединениям, которые привязаны к указанному `user_id`.

## Ключевые измененные файлы

*   `token_storage.py`: Переделан для работы с директорией `user_tokens/` и `user_id`.
*   `centrifugo_listener.py`: Добавлен `ListenerManager`, сам `CentrifugoListener` теперь работает для конкретного `user_id` и использует `broadcast_to_user`.
*   `websocket_manager.py`: Переделан для хранения соединений по `user_id` и адресной рассылки.
*   `main.py`: Обновлена логика старта/остановки (`ListenerManager`), OAuth коллбэка (получение `user_id`, сохранение в сессию, запуск/перезапуск слушателя), WebSocket эндпоинта (привязка к `user_id` из сессии), эндпоинта статуса.
