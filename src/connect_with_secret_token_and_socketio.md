# Проблемы и решения при подключении к WebSocket DonationAlerts

При попытке настроить получение уведомлений о донатах через WebSocket DonationAlerts мы столкнулись с несколькими проблемами. Вот их описание и найденные решения:

## Проблема 1: Подключение через Centrifugo и поиск `USER_ID`

*   **Первоначальный подход:** Основываясь на официальной документации API (`https://www.donationalerts.com/apidoc`), мы попытались подключиться к WebSocket-серверу Centrifugo по адресу `wss://centrifugo.donationalerts.com/connection/websocket`.
*   **Требование:** Для подписки на канал донатов (`$alerts:donation_<user_id>`) требовался **числовой `USER_ID`**.
*   **Сложность:** В интерфейсе настроек DonationAlerts (включая "Основные настройки") **не удалось найти** явно указанный числовой `USER_ID`. Вместо него использовался строковый никнейм.
*   **Блокер:** Без числового `USER_ID` подписка на канал Centrifugo была невозможна.

## Проблема 2: Ошибка аутентификации при использовании "Secret Token"

*   **Попытка решения:** Чтобы получить числовой `USER_ID` (и для дальнейшей аутентификации в Centrifugo), мы модифицировали скрипт для выполнения HTTP GET-запроса к API профиля (`/api/v1/user/oauth`). Для аутентификации этого запроса мы использовали **"Secret Token"**, найденный в "Основных настройках", как `Bearer` токен.
*   **Результат:** Запрос к HTTP API завершился с ошибкой **`401 Unauthorized`** (`{"message":"Unauthenticated."}`).
*   **Вывод:** "Secret Token" из основных настроек **не подходит** для аутентификации стандартных запросов к HTTP API v1. Для работы с этим API (и, следовательно, с Centrifugo WebSocket, как описано в документации) требуется получение временного **OAuth `access_token`** через стандартный OAuth 2.0 флоу (с использованием `client_id` и `client_secret` зарегистрированного приложения). Это значительно усложняло первоначальную задачу.

## Решение: Альтернативный путь через Socket.IO и Токен Виджета

*   **Обнаружение:** Исследование показало наличие другого, более простого способа подключения, который используют виджеты DonationAlerts. Этот способ работает через стандартный протокол **Socket.IO** и другой WebSocket endpoint: `wss://socket.donationalerts.ru:443`.
*   **Ключевой элемент:** Для аутентификации в этой системе используется не "Secret Token" и не OAuth `access_token`, а специальный **"Токен виджета"**.
*   **Поиск токена:** "Токен виджета" был найден в разделе **"Настройки" -> "Виджеты" -> "Оповещения"**. В ссылке для встраивания виджета (`https://www.donationalerts.com/widget/alerts?group_id=1&token=...`) параметр `token` содержал нужное значение. В данном случае он совпал с "Secret Token", но важно было взять его именно из настроек виджета.
*   **Реализация:**
    *   Скрипт был переписан с использованием библиотеки `python-socketio`.
    *   Адрес подключения изменен на `wss://socket.donationalerts.ru:443`.
    *   Логика аутентификации заменена на отправку события `add-user` с "Токеном виджета" после установки соединения.
    *   Поиск `USER_ID` и HTTP-запросы стали ненужными для этого метода.

## Результат

Скрипт, использующий Socket.IO и "Токен виджета", успешно подключается к серверу (`wss://socket.donationalerts.ru:443`), отправляет токен для аутентификации и переходит в режим ожидания сообщений.

Тестовое оповещение, отправленное через интерфейс DonationAlerts, подтвердило:
*   Скрипт успешно получает события.
*   Имя события для донатов - `'donation'`.
*   Данные доната приходят в виде **строки JSON**, которую необходимо парсить.
*   Основные поля (`username`, `amount`, `currency`, `message`) присутствуют и извлекаются корректно.

**Задача получения донатов через WebSocket и записи их в файл решена.**
